# Terminal dwell: обученный эксперимент v1

Модель оценивает часы от завершения DISCHARGE до завершения TRUCK_OUT входящего контейнера.
Модель обучена на операционной истории анонимизированного терминала. На Каспии качество не проверено.
Предиктор готовности к исходящему парому этим экспериментом не обучался.

Дата прогона: 2026-11-12T11:59:45.983114+00:00. Источник: [Mendeley v2](https://data.mendeley.com/datasets/yvp2b4rtp3/2), DOI 10.17632/yvp2b4rtp3.2, CC BY 4.0.
Авторы данных: Hanung Nindito Prasetyo, Riyanarto Sarno, Kelly Rossa Sungkono, Indra Waspada, Raden Budiraharjo.

## Модель и входы

CatBoost MultiQuantile, глубина 4; сохранено 68 деревьев после early stopping. Предсказывает P10/P50/P90.
Входы: размер и тип контейнера, масса, локальные час и день недели.
Case ID, фактический выезд, длительность и будущие таможенные события в признаки не входят.
Сезон, погода, портовая очередь, вместимость и cutoff на этих данных не обучались.

Из 95,587 подготовленных случаев исключены 18,022 с неоднозначным масштабом массы. Остались 77,565 записей с GROSS в диапазоне 1–60. Правило не переводит предполагаемые килограммы в тонны; это ограничение популяции эксперимента.

## Результаты временной проверки

| Метод | MAE, часы | RMSE, часы | Медианная абсолютная ошибка, часы |
| --- | ---: | ---: | ---: |
| global_median | 50.21 | 66.27 | 46.47 |
| type_size_median | 48.88 | 65.71 | 43.30 |
| random_forest | 59.67 | 73.66 | 54.75 |
| random_forest_log | 47.47 | 66.60 | 37.74 |
| catboost | 48.62 | 65.42 | 41.81 |

CatBoost уменьшил MAE относительно общей медианы на 3.17%. Random Forest на log1p-цели дал меньшую ошибку точечного прогноза.
Интервал CatBoost P10–P90 покрывает 68.6% исходов при номинальных 80%; средняя ширина 172.1 часа.
Эти интервалы пока не откалиброваны. Выигрыш невелик; модель предназначена для эксперимента, не для эксплуатационных обещаний.
Выбор для API: вариант CatBoost с минимальной validation pinball loss среди двух глубин; Random Forest служит сравнением точечных прогнозов.

Дополнительно проверен фактический Monte Carlo fallback на тех же 14 542 случаях,
с неизменёнными defaults: minimum=0, typical=48, maximum=168 часов, seed=42, 2000 samples.
Его MAE — **47,75 часа**, покрытие P10–P90 — **47,4%**. По точечной ошибке он немного
лучше CatBoost (48,62), немного хуже Random Forest log (47,47). Интервал CatBoost
покрывает 68,6% исходов; обе ветки не достигают номинальных 80%.
Преимущество обученной модели по точечному прогнозу над этим fallback не установлено.
Это дополнительное сравнение на уже использованном тесте; небольшие различия не
объявляются статистически значимыми. [Параметры и полные метрики](fallback-comparison.json).
Воспроизведение: `uv run --group ml python -m scripts.benchmark_dwell_fallback` из backend/.

Полные метрики, параметры, версии пакетов и hashes: [report.json](report.json). Сырые результаты временного теста: [test-predictions.csv](test-predictions.csv).
Веса: model.cbm, контракт и контрольная сумма: metadata.json.

## Запуск

```bash
cd backend
uv sync --locked --group ml
uv run --group ml python -m scripts.train_terminal_dwell
uv run --group ml uvicorn app.main:app --host 127.0.0.1 --port 8000
```

API: POST /api/v1/predictions/terminal-dwell; состояние: GET /api/v1/models/terminal-dwell.
Без ML-зависимостей, весов или корректного пакета backend использует Monte Carlo fallback.
При mode=algorithm fallback используется явно. method, trained_on_history и fallback_reason показывают фактическую ветку.
Сценарный fallback использует отдельный диапазон длительностей из запроса; его точность этой проверкой не измерялась.

После изменения пакета модели backend нужно перезапустить. CASPIAN_DWELL_MODEL_DIR задаёт путь; пустое значение отключает ML.
Существующий /predictions/readiness продолжает моделировать другую задачу — готовность к cutoff. frontend/ не изменялся.
