# Terminal dwell v2: CatBoost с историей операций

Простой CatBoost MultiQuantile: глубина 4, 92 дерева, P10/P50/P90.
Цель прежняя: часы от конца DISCHARGE до конца TRUCK_OUT входящего контейнера.
Терминал анонимизирован; на Каспии качество не подтверждено.

К пяти признакам v1 добавлены шесть чисел из уже завершённых событий:
время с BAPLIE и VESSEL_ATB, число известных операций, признаки завершённых
CUSTOMS_DEL и JOB_DEL, время с последней операции. DISCHARGE служит точкой отсчёта;
TRUCK_OUT и будущие события исключены. Отсутствующая длительность — NaN.
Источник не содержит `recorded_at`: конец события — приближение доступности информации.

Обучение: те же 21 129 июльских случаев с исходами до 1 августа.
Выбор глубины 4/6: 7592 случая с прогнозами 1–8 августа.
Калибровка: отдельные 6956 случаев с прогнозами 9–15 августа; исходы известны до сентября.
Для каждого квантиля рассчитана поправка по остаткам калибровочной части.
Сентябрьские исходы для обучения и калибровки не использовались.

## Результат на прежних 14 542 сентябрьских случаях

| Метод | MAE, часы | Покрытие P10–P90 | Средняя ширина интервала, часы |
| --- | ---: | ---: | ---: |
| Monte Carlo с прежними defaults | 47,75 | 47,4% | 93,3 |
| CatBoost v1 | 48,62 | 68,6% | 172,1 |
| CatBoost v1 с такой же калибровкой | 42,52 | 75,3% | 150,7 |
| CatBoost с историей, без калибровки | 35,41 | 71,6% | 118,0 |
| **CatBoost v2 с историей и калибровкой** | **32,10** | **82,3%** | **113,0** |

Улучшение относительно v1 — около 34% по MAE. Выигрыш объясняется и историей,
и калибровкой. Номинальное покрытие — 80%; результат 82,3% относится к этой выборке
и не гарантирован для будущего периода.

Сентябрь уже изучался в предыдущих экспериментах: это исследовательская проверка,
не независимое подтверждение. Смещение завершённых случаев у конца выгрузки остаётся.
v1 использовал весь августовский validation, поэтому сравнение также не является
полностью симметричным новым соревнованием моделей. Данных для подтверждения
исходящего парома и работы на Каспии нет.

V2 разрешён к использованию по августовскому validation: pinball loss лучше v1 и MC,
MAE не хуже лучшего из них более чем на 2%. Правило не использует сентябрьский тест.
Конфигурация, поправки, hashes и метрики: [report.json](report.json).
Веса и контракт: [metadata.json](metadata.json), `model.cbm`.

## API для фронтендера

`POST /api/v1/predictions/terminal-dwell`, авторизация и API-ключ не нужны.
`observed_at` — момент завершения выгрузки. Передавать всю известную к этому моменту
историю завершённых операций; для v2 нужны как минимум BAPLIE и VESSEL_ATB.
Отсутствие операции в полной истории означает, что она ещё не завершилась.
Частичную историю нельзя выдавать за полный журнал.

```json
{
  "observed_at": "2026-11-12T12:00:00+03:00",
  "container_size": 20,
  "container_type": "DRY",
  "gross_tonnes": 15,
  "history": [
    {"activity": "BAPLIE", "completed_at": "2026-11-10T12:00:00+03:00"},
    {"activity": "VESSEL_ATB", "completed_at": "2026-11-11T12:00:00+03:00"}
  ]
}
```

С полной историей `method=catboost_terminal_dwell_v2`. Без истории или при её
недостаточности остаётся v1; без исправных моделей — алгоритм.
Недоступность/ошибка v2 не отключает исправный v1. `mode=algorithm` сохранился.
Будущие, дублированные события и завершённый TRUCK_OUT дают HTTP 422.
Поля ответа прежние: `remaining_hours`, `release_at`, `method`, `model_version`,
`trained_on_history`, `fallback_reason`, `warnings`.

`GET /api/v1/models/terminal-dwell` дополнительно сообщает `history_loaded`,
`history_model_version`, `history_load_error`. Старые `loaded`/`model_version`
описывают базовую модель. [TypeScript-контракт](../../../api/public-data.types.ts)
обновлён; существующий `predictTerminalDwell()` принимает необязательную историю.
Frontend не менялся, браузерный поток не проверялся.

Проверки: 89 тестов backend, Ruff, компиляция публичного TypeScript-клиента.
На 25 записях из исходного журнала HTTP-ответы совпали с офлайн-квантилями точно:
[протокол проверки](http-verification.json). Для replay неизвестная timezone источника
представлена единым условным +00:00; это сохраняет часы и интервалы, не устанавливая
фактический часовой пояс терминала.

## Воспроизведение и запуск

```bash
cd backend
uv sync --locked --group ml
uv run --group ml python -m scripts.prepare_dwell_history
uv run --group ml python -m scripts.train_dwell_history
uv run --group ml uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Нужны проверенные XLSX и CSV v1 в `backend/var/`: см.
[источники обучения](../../../data/training/README.md).
`CASPIAN_DWELL_HISTORY_MODEL_DIR` задаёт каталог v2, пустое значение отключает v2.
`CASPIAN_DWELL_MODEL_DIR` управляет базовым v1. Пакеты загружаются при старте;
после смены весов нужен restart. Без optional ML-зависимостей используется алгоритм.
