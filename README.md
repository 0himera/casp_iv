# Caspian Transit

Прототип по кейсу [Smart Caspian Transit](case.md): единое окно логиста для
сравнения мультимодальных маршрутов, оценки риска пропустить паром и согласования
версии документов и маршрута в Casper testnet.

**[Открыть демо](https://caspian.psychaos.art)** ·
[Swagger API](https://caspian.psychaos.art/docs) ·
[Сценарий защиты](docs/NEXT_STEPS.md)

## Что работает

- Полноэкранная карта каспийских портов и одно плавающее окно с анимированным сворачиванием: маршруты, прогноз,
  документы или порты. Сеть опубликованных коридоров и мультимодальный граф.
- Сравнение **ж/д → порт → море** и **авто → порт → море**. Отдельные задержки ж/д
  и авто влияют на готовность груза и риск пропуска cutoff парома.
- Серверный Monte Carlo: готовность P10/P50/P90, риск пропустить рейс и ETA доставки.
  Четыре варианта ведут к одному пункту назначения; расчёт начинается от текущей
  сценарной позиции груза. Погода и история активности портов получаются из открытых источников.
- Единый расчёт CO₂e по массе, расстояниям плеч и коэффициентам для ж/д, авто и моря.
  Интерфейс показывает тот же итог и разбивку, что и API.
- Версионируемый паспорт: выбор маршрута, загрузка новой версии документа,
  согласования трёх ролей, журнал изменений и ссылки на транзакции Casper testnet.
- Постоянное хранение в SQLite и отдельный worker. Статусы `queued` и `submitted`
  не считаются подтверждением; UI обновляет паспорт после `confirmed`.

## Данные и границы прототипа

| Источник | Что используем |
| --- | --- |
| Open-Meteo | Прогноз погоды в портах, время получения и признак устаревания |
| IMF PortWatch | Исторические оценки судозаходов по AIS, не фактическая очередь терминала |
| Курык / ASCO | Опубликованные диспозиции судов с датами и источниками |
| Каталог проекта | 11 портов России, Ирана, Казахстана, Азербайджана и Туркменистана; покрытие источников различается |

Груз и его движение демонстрационные. Расписания, вместимость, терминальная очередь,
скорости и ESG-коэффициенты — **явные сценарные допущения**, доступные в интерфейсе.
Публикация коридора не подтверждает действующий рейс или свободные места. Морские
линии проверены по маске воды для отображения; это не навигационные маршруты.

Основной прогноз стыковки — прозрачный Monte Carlo с открытой погодой и сценарными
правилами обработки портовой активности. Его точность на реальных каспийских
перевозках пока не подтверждена: событий конкретных грузов от оператора нет.

Отдельно обучены **CatBoost v1/v2** для времени от выгрузки входящего контейнера
до выезда из терминала. V2 использует историю завершённых операций; при её
недостаточности используется v1, при недоступности моделей — алгоритмический fallback.
Это другая задача, её результат не подставляется автоматически вместо готовности
к исходящему парому. Данные анонимизированного терминала, метрики и ограничения:
[модель v2](models/terminal-dwell/v2/README.md), [источники обучения](data/training/README.md).

## Для чего блокчейн

Rust/Odra-контракт `TransitPassport` развёрнут в **Casper testnet**. Он фиксирует
версии и хеши документов/маршрута, решения трёх назначенных ролей и сроки согласований.
Полные документы хранятся вне блокчейна. Смена маршрута или документа создаёт новую
версию и требует повторного согласования; пересчёт прогноза паспорт не меняет.

Транзакции подписывает серверный worker. Роли демо: логист, перевозчик и имитатор
таможенного сервиса. Статус «Комплект согласован» означает согласование версии
участниками, а не юридический таможенный выпуск.

## Стек и архитектура

- **Frontend:** Next.js 16, React, TypeScript, TanStack Query, MapLibre, React Flow.
- **Backend:** Python 3.12+, FastAPI, HTTPX, SQLite, отдельный Casper-worker.
- **Прогноз:** Monte Carlo; отдельный эксперимент CatBoost MultiQuantile.
- **Контракт:** Rust / Odra, Casper testnet.

```text
Браузер → Next.js /api/backend → FastAPI /api/v1 → SQLite / расчёт / открытые источники
                                                   ↓
                                              outbox → worker → Casper testnet
                                                   ↑                 ↓
                                                   └─ проверенная проекция
```

Работающее демо развёрнуто на VPS: Next.js, FastAPI, SQLite и Casper-worker
работают как systemd-сервисы. Домен обращается к ним напрямую через nginx;
машина разработки и SSH-туннель больше не участвуют в обслуживании сайта.
На VPS ML-веса отключены: terminal-dwell использует алгоритмический fallback,
основной Monte Carlo-прогноз стыковки работает как прежде.
[Развёртывание и обновление](infra/vps/README.md).

## Быстрый запуск фронта с действующим demo API

Нужны Git, Node.js и Bun. Команды выполняются из корня репозитория:

```bash
cd frontend
bun install --frozen-lockfile
CASPIAN_API_URL=https://caspian.psychaos.art/api/v1 bun run dev
```

Открыть `http://localhost:3000`. Браузер использует `/api/backend`, Next.js обращается
к указанному `CASPIAN_API_URL`. Preview-токены ролей намеренно опубликованы командой
в репозитории. Это общее тестовое окружение, не полноценная авторизация пользователей.
Signing keys Casper фронтенду не передаются.

## Локальный backend

Нужны Python 3.12+ и uv. Из корня репозитория:

```bash
cd backend
uv sync --locked --group ml
uv run --group ml uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Swagger: `http://localhost:8000/docs`, health: `http://localhost:8000/api/v1/health`.
В другом терминале из корня запустить frontend с локальным API:

```bash
cd frontend
bun install --frozen-lockfile
CASPIAN_API_URL=http://127.0.0.1:8000/api/v1 bun run dev
```

По умолчанию локальный backend работает без записи в chain; новая SQLite-база
не содержит отправок. Доступны открытые данные и публичные расчёты
`/predictions/readiness` и `/predictions/terminal-dwell`. Для полного
сквозного сценария нужны настройки записи, отдельный worker, `casper-client` и ключи
адресов, назначенных в используемом контракте. Для собственного набора адресов нужен
соответствующий deployment. [Настройка API и worker](docs/TRANSIT_API.md).
Закрытые ключи и рабочие базы не входят в Git; `.env` автоматически не загружается.

## Проверки

Из соответствующих каталогов:

```bash
# backend/
uv run --group ml pytest -q
uv run ruff check app tests
uv run python -m app.export_contract

# frontend/
bun test
bun run lint
bun run build
```

На 13.11.2026 проверены **104 backend-теста и 24 frontend-теста**, Ruff, ESLint,
TypeScript и production build. Браузерный сценарий прошёл создание паспорта,
смену маршрута, три согласования и замену файла через настоящий Casper testnet;
хеши документов и маршрута сверены с chain state. См. [протокол](backend/evidence/case-flow-2026-11-13.json).

### Сменить порты отправки

В «Маршрутах» выберите «Откуда» и «Куда». Предпросмотр строится по морской маске;
стрелки меняют направление. «Сохранить маршрут» у логиста пересчитывает прогноз/ESG
и записывает новую версию паспорта в Casper. Поддержаны 54 пары между 11 портами
в обе стороны; Астрахань–Оля требует отдельного речного маршрута. Портовые и речные
подходы не нарисованы и учитываются в расчёте приближённо. Рейс и места не бронируются.
