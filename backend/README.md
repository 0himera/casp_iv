# Caspian Flow backend

Первый рабочий модуль backend — открытые данные о портах Каспия. FastAPI получает реальную погоду Open-Meteo и дневную активность IMF PortWatch без ключей. В каталоге 11 портов пяти стран; у восьми подтверждены координаты и PortWatch ID. Для Курыка, Алята и Оли данные пока явно ограничены, соседний порт автоматически не подставляется.

Это сервис данных. API отправок, прогноз задержек и контракт Casper пока остаются отдельными этапами. Существующий mock на 4010 нужен для действий с демонстрационной перевозкой; новый сервис работает на 8000.

## Запуск

Python 3.12+ и uv. Из корня репозитория:

```bash
cd backend
uv sync --locked
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000
```

- Swagger UI: http://localhost:8000/docs
- OpenAPI: http://localhost:8000/openapi.json
- Health: http://localhost:8000/api/v1/health

Настройки читаются из переменных окружения; `.env.example` — образец, сам по себе файл `.env` автоматически не загружается. Значения по умолчанию позволяют запустить сервис без конфигурации. Если нужен env-файл: `uv run --env-file .env uvicorn app.main:app --port 8000`.

## API

| Метод и путь | Результат |
| --- | --- |
| `GET /api/v1/health` | Готовность локального сервиса; внешние источники при health не опрашиваются |
| `GET /api/v1/ports` | Каталог, координаты и доступность источников |
| `GET /api/v1/ports/{id}` | Один порт |
| `GET /api/v1/ports/{id}/weather?forecast_days=3` | Почасовой ветер, порывы, температура, осадки; от 1 до 7 календарных дней UTC |
| `GET /api/v1/ports/{id}/activity?days=30` | Судозаходы за последние 1–90 завершённых дней UTC |

Пример:

```bash
curl 'http://localhost:8000/api/v1/ports/makhachkala/weather?forecast_days=1'
curl 'http://localhost:8000/api/v1/ports/aktau/activity?days=30'
```

Weather сохраняет `null`, исходные единицы и координаты модельной сетки. `issued_at=null`: время выпуска модели не выводится из времени HTTP-запроса. Ряды начинаются в начале календарного дня, поэтому UI выбирает нужный интервал по полному `time`, а не по индексу.

Activity возвращает фактические строки источника; отсутствующие дни перечислены в `missing_dates`, не заполняются нулями. `latest_available_date` — последний день с записью в запрошенном окне, не глобальная дата последней публикации. Нулевое значение источника сохраняется как ноль. Эти данные — оценка активности, не очередь, не загрузка причалов в процентах и не задержка груза.

`meta` содержит источник, атрибуцию, `fetched_at`, `source_updated_at`, качество и состояние кэша. Здесь `source_updated_at=null`, потому что используемые ответы не предоставляют надёжное время публикации. Не подменять его датой наблюдения.

`cache_status=live` означает успешный HTTP-запрос к источнику, а не live-наблюдение. Поэтому одновременно возможны `cache_status=live` и `stale=true`: например, в свежем ответе PortWatch последняя запись старше трёх дней. Порог три дня — эвристика отображения, не SLA поставщика.

При сбое источника отдаётся последний снимок с `cache_status=stale`; его дата сохраняется. Если старый activity snapshot относится к предыдущему календарному окну, ответ сохраняет старые `window_start/window_end` и содержит предупреждение `CACHED_WINDOW_DIFFERS_FROM_CURRENT_REQUEST`. UI должен показывать фактически возвращённый диапазон. Если снимка нет — 503 `SOURCE_UNAVAILABLE`, с `Retry-After`. Неподдержанный источник/неподтверждённые координаты — 422, неизвестный порт — 404.

## Стек и устройство

```text
Next.js → FastAPI routes → DataService → HTTPX → Open-Meteo / IMF PortWatch
                              ↕
                       SQLite snapshots
```

- `app/main.py` — HTTP-маршруты, lifecycle, CORS и единый формат ошибок.
- `app/models.py` — Pydantic DTO и валидация единиц/значений.
- `app/catalog.py` — чтение общего `data/ports.json`.
- `app/providers.py` — запросы и нормализация внешних JSON.
- `app/service.py` — свежесть, fallback, дедупликация и ограничение параллелизма.
- `app/cache.py` — последний корректный нормализованный и исходный ответ для каждого ключа.

Модульный монолит: один процесс uvicorn, SQLite для локального кэша. TTL погоды 30 минут, активности 6 часов; после ошибки cooldown 60 секунд. Одновременно не более четырёх upstream запросов, запросы одного ключа объединяются. На внешний запрос есть общий deadline и ограничение размера ответа 2 MB. Локальные ошибки БД не маскируются под успешный upstream ответ.

Кэш сохраняется в `backend/var/public-data.sqlite3`, исключён из Git. Это не архив истории и не хранилище перевозок: на ключ сохраняется один последний снимок. Locks/cooldown действуют в одном процессе; для нескольких replicas нужен общий механизм координации и отдельная БД. Рабочие сущности перевозок позже вынесем в PostgreSQL. Rust/Odra будет отдельным adapter для подписей и состояния паспорта, без переноса погодных расчётов в chain.

## Подключение frontend

Использовать `api/public-data.client.ts` и `api/public-data.types.ts` из корня. Новый base URL — `http://localhost:8000/api/v1`, без Authorization. CORS по умолчанию разрешает localhost:3000 и 127.0.0.1:3000.

Не заменять пока `NEXT_PUBLIC_API_BASE_URL` для отправок: этот URL остаётся на 4010. Для нового клиента удобно добавить `NEXT_PUBLIC_DATA_API_BASE_URL=http://localhost:8000/api/v1`. Это имя для интеграции; текущий frontend его ещё не читает.

```ts
const dataApi = createPublicDataClient('http://localhost:8000/api/v1');
const ports = await dataApi.ports();
const weather = await dataApi.weather('makhachkala', 3);
const activity = await dataApi.activity('makhachkala', 30);
```

На карте отображать только ports с координатами; отображать недоступность источников отдельно. График погоды заменить данными API, явно указав порт, даты и единицы. PortWatch показывать отдельным графиком дневной активности; не конвертировать counts в проценты загрузки или часы задержки.

## Проверки и контракт

```bash
uv run pytest -q
uv run ruff check app tests
uv run python -m app.export_contract
```

Тесты используют HTTPX MockTransport, сеть им не нужна. Покрывают корректные ответы, пропуски и нули, таймауты, malformed upstream, сроки кэша, перезапуск, UTC midnight, CORS и конкурентные запросы. Экспорт обновляет `api/public-data.openapi.json` и `api/public-data.types.ts`; контракт отправок не меняется.

Проверено 12.11.2026: 27 тестов, Ruff и TypeScript-проверка нового клиента прошли. Через скомпилированный TypeScript-клиент выполнены HTTP-запросы к запущенному uvicorn по всем восьми портам с покрытием: каждый вернул 24 часа погоды и две записи активности в семидневном окне; последняя дата активности — 06.11.2026, `stale=true`. Это проверка client → backend → внешние API/кэш → DTO. Подключение этих данных к существующим React-компонентам и браузерный прогон ещё впереди. TestClient выдаёт предупреждение Starlette о будущей замене тестового HTTP-транспорта; тесты выполняются успешно.

Не реализованы в этом срезе: волны по морским точкам, parser Курык/ASCO, реальная история отправок, обучаемый прогноз и Casper testnet. Источники и подтверждённое географическое покрытие описаны в [DATA_SOURCES.md](../docs/DATA_SOURCES.md).
