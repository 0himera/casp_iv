# Фактические данные и сценарные элементы

Проверка backend `main` и фронтенд-ветки `origin/frontend` на commit `eb22279`.
Фронтенд не изменялся. Наличие публичного источника и факт его текущей доступности —
разные вещи; API возвращает дату получения, статус кэша и признак устаревания.

## Что уже можно подключить без ключа

`GET /api/v1/live-overview` возвращает данные всех 11 портов: погоду Open-Meteo,
суточные оценки судозаходов IMF PortWatch и опубликованные диспозиции Курык/ASCO.
У каждого порта отдельно `weather`, `activity`, `sailings` и соответствующие `*_error`.
При недоступности или отсутствии покрытия значение `null`, а причина доступна в ошибке.
Если есть последний сохранённый снимок, API возвращает его с `stale=true`, не называя live.

Отдельные endpoints: `/ports`, `/ports/{id}/weather`, `/ports/{id}/activity`,
`/sailings?port_id=...`, `/corridors`. Типизированный клиент: `liveOverview()`.
Погодные данные — прогноз на модельной сетке, не наблюдение на причале. Судозаходы —
оценки AIS по дням, не проценты загрузки, не текущая очередь и не время обработки груза.
Диспозиции — сообщения операторов, не бронирование и не подтверждение мест.
Каталог коридоров включает исторические/планируемые сообщения, не гарантирует рейс сегодня.

При проверке 12.11.2026 weather ответил для 9 портов, activity для 8; у Алята и Оли
координаты не подтверждены, у Курыка нет подтверждённого PortWatch ID. Диспозиции
удалось получить для Курыка, Алята и Туркменбаши. Фактические даты отдельных публикаций,
возможная задержка PortWatch и время опроса доступны в ответе; не все данные свежие.
[Сводка проверки](../backend/evidence/live-overview.json).

## Что ещё остаётся demo

| Где | Сейчас | Что требуется для actual |
| --- | --- | --- |
| Backend `POST /shipments` | Только `template=demo`; масса, маршрут, прогноз и документы — fixture | Источник данных конкретного груза или ввод пользователя с подтверждением происхождения; отдельный контракт создания без fixture |
| Backend `/shipments/{id}/forecast` | Monte Carlo по переданным сценарным временам, cutoff и вместимости | Проверенные события груза, расписания, подтверждённая вместимость и модель связи погоды/загрузки с задержкой |
| Backend CatBoost | Обучен на анонимном терминале на импортной обработке | Каспийские метки и валидация на задаче исходящего рейса |
| Backend ESG | Сценарий по переданным расстояниям и коэффициентам | Проверенные плечи, тоннаж, методика и коэффициенты; данные об эксплуатации по возможности |
| Frontend `cargoQueries.ts`, `mockTransitData.ts` | Фиксированные грузы, порты и погода | Подключить `liveOverview()`; отдельно получить подтверждённый источник грузов |
| Frontend `shipmentApi.ts` | Seed при offline и как initialData | Показывать отсутствие данных/ошибку вместо seed; подключить реальный API |
| Frontend `corridorRoutes.ts`, `enrichShipment.ts` | Локально добавленные маршруты с фиксированными ETA, ценой и риском | Данные маршрута из backend/оператора; неизвестные значения показывать пустыми |
| Frontend `scenarioTransitions.ts`, `RecommendationBanner.tsx` | Зашитые риск, ветер, волны, рекомендованный маршрут | Показывать источник, время и качество; без подтверждённой модели не утверждать фактический риск |
| Frontend `esgEngine.ts` | Фиксированные выбросы, baseline и рейтинг | Использовать расчёт API с известными исходными данными; рейтинг без методики убрать |
| Frontend `attestationTransitions.ts` | Локальная имитация согласований | Отображать только подтверждённые Casper-операции и состояние backend |

Для живого цифрового двойника нужны данные конкретного груза. Открытые данные портов
и погоды не содержат его маршрут, документы, фактические этапы, цену или бронирование;
создавать такие сведения из портовой статистики нельзя.
