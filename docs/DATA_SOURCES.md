## Проверенные запросы

```text
https://api.open-meteo.com/v1/forecast?latitude=46.35&longitude=48.04&hourly=wind_speed_10m,wind_gusts_10m,precipitation,visibility&forecast_days=1&timezone=UTC
https://marine-api.open-meteo.com/v1/marine?latitude=43&longitude=50&hourly=wave_height,wave_period&forecast_days=1&timezone=UTC
```

Необработанные ответы сохранены в `data/sources/open-meteo-weather.json` и `data/sources/open-meteo-marine.json`; сведения о запросах — `data/sources/manifest.json`. В UI fixture эти live-значения автоматически не подмешиваются: демонстрационные прогнозы должны быть воспроизводимы.

API вернул координаты модельной сетки, отличающиеся от запрошенных. Сохранять оба набора. Единицы читать из `hourly_units`, не предполагать м/с: в проверенном weather запросе ветер возвращается в км/ч. Учитывать атрибуцию Open-Meteo и поставщика модели; условия выбранного доступа проверить перед публичным коммерческим использованием.

## Что запросить у организаторов

Готовый текст для отправки самостоятельно:

> Для прототипа прогноза мультимодальных задержек нужны обезличенные данные за несколько месяцев: ID отправки, маршрут и тип груза, плановые и фактические прибытие/убытие по этапам, время входа и выхода из очереди терминала, начало/окончание обработки, подача/готовность документов и причины задержек. Нужны расписания судов с cutoff приёма груза, доступная вместимость, ограничения по погоде и совместимости груза. Просим указать часовые пояса, единицы, время появления данных в системе, разрешённое использование и возможность показать обезличенные примеры на защите. Есть ли sandbox/API для pre-clearance и тестовые статусы?

Не предполагается автоматическая отправка этого сообщения.

## Первичный контракт данных

`shipment_id, event_type, planned_at, actual_at, recorded_at, location_id, source_id, reason_code` — события этапов. `recorded_at` нужен для обучения без утечки будущих сведений. Все timestamp UTC, оригинальный timezone сохранить отдельно.

`sailing_id, departure_port, arrival_port, cargo_cutoff, departure_at, arrival_at, capacity, capacity_unit, observed_at, source_id` — расписания; неизвестная ёмкость — null, не 0.

`location, variable, value, unit, valid_at, issued_at, fetched_at, source_id` — погода. Для PDF дополнительно URL, SHA-256 файла, дата публикации и ручная/автоматическая проверка извлечения.

## Решение для хакатона

Подключать реальную погоду, использовать проверенные портовые сведения как датированные ограничения, расписание/очередь/фактическое движение — только предоставленные организаторами данные либо явная синтетика. Никакие числа текущей загрузки, доступность мест и регулярность демонстрационных рейсов не заявлять как подтверждённые.

## Покрытие стран Каспия

Дополнительная проверка 12.11.2026: открытый REST API IMF PortWatch возвращает данные без ключа для восьми целевых портов. Справочник координат и идентификаторов сохранён в `data/ports.json`; это слой покрытия источников, не перечень подтверждённых транспортных линий.

| --- | --- | --- |
| Россия, Дагестан | Махачкала | port684 |
| Россия | Астрахань | port76 |
| Казахстан | Актау | port16 |

Источник идентификаторов и координат — [PortWatch ports REST layer](https://services9.arcgis.com/weJ1QsnbMYJlCHdG/arcgis/rest/services/PortWatch_ports_database/FeatureServer/0). Курык, Оля и Алят не обнаружены отдельными строками в выполненной географической выборке; не подменять их соседними портами. Баку не считать автоматически эквивалентом терминала Алят.

[Daily Ports REST layer](https://services9.arcgis.com/weJ1QsnbMYJlCHdG/arcgis/rest/services/Daily_Ports_Data/FeatureServer/0) отдаёт дневные судозаходы по типам и оценки import/export. Последняя строка у всех восьми портов в проверке — 2026-11-06. Это агрегированный исторический индикатор активности, не live-очередь, свободные места или фактическая задержка конкретного контейнера. Нулевое значение AIS-оценки не доказывает отсутствие движения. Время публикации и полноту истории ещё нужно проверить при построении датасета.

Проверяемый запрос по Махачкале:

```bash
curl --get 'https://services9.arcgis.com/weJ1QsnbMYJlCHdG/arcgis/rest/services/Daily_Ports_Data/FeatureServer/0/query' \
  --data-urlencode "where=portid='port684'" \
  --data-urlencode 'outFields=portid,portname,date,portcalls,import,export' \
  --data-urlencode 'orderByFields=date DESC' \
  --data-urlencode 'resultRecordCount=7' \
  --data-urlencode 'returnGeometry=false' \
  --data-urlencode 'f=json'
```

Open-Meteo дополнительно проверен одним запросом по координатам всех восьми портов: для каждого получены 24 непустых почасовых значения ветра. `data/sources/weather-coverage.json` содержит URL и результаты проверки. Это проверка атмосферной погоды; покрытие волн по всем точкам ещё не проверено. [Условия доступа](https://open-meteo.com/en/pricing): free endpoint предназначен для некоммерческого использования/прототипирования, нужен credit источнику; коммерческий доступ отдельно.

Это открытый HTML, документированного API пока не найдено. Уместен небольшой parser со снимком страницы и временем её обновления. [Очередь на погрузку](https://portkuryk.kz/ru/queue) найдена как ссылка, но чтение завершилось timeout; доступность содержимого не подтверждена.
- **Азербайджан, Казахстан, Туркменистан:** [таблица ASCO](https://cabinet.asco.az/passenger-ticket) открыта без входа; при проверке показывает движения и статусы паромов Алят—Курык и Алят—Туркменбаши, в том числе погодные ожидания. HTML, не подтверждённый публичный API. Точное заранее фиксированное расписание нельзя предполагать: [ASCO объясняет зависимость отправления от погоды и загрузки](https://asco.az/en/pages/66).

## Поток координат судов

[AISStream](https://aisstream.io/) предлагает бесплатный WebSocket, ключ создаётся после входа через GitHub. Endpoint: `wss://stream.aisstream.io/v0/stream`. Подключать с backend: браузерные подключения сервисом не разрешены. Прежде чем включать на карту, измерить покрытие Каспия, задержку сообщений и наличие конкретных MMSI. В этой проверке ключ не создавался и live-поток не подключался; API availability не означает подтверждённое покрытие каждого порта.

## Порядок подключения

1. Open-Meteo — погода по восьми портам; источники и UTC timestamps.
2. PortWatch — историческая активность, отдельным индикатором с датой записи.
3. Курык + ASCO — текущие опубликованные диспозиции, с `source_updated_at` и `fetched_at` отдельно.
4. AISStream — исключён из текущего этапа по выбору пользователя: использовать только источники без ключа. Справочная информация выше сохранена для будущего рассмотрения.
5. Для документов, pre-clearance, поездов, цены/вместимости и связи контейнер—судно остаются нужны данные организаторов/операторов. Публичного готового API этих сведений в исследовании не подтверждено.

Публичная читаемость страницы сама по себе не задаёт лицензию массового использования. Для пилота условия каждого источника фиксируются отдельно; текущие проверки — небольшие read-only запросы.
